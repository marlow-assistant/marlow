End of the day. Two jobs tonight, in this order. The first is not optional
and does not depend on the second.

Today's date is in the context line at the top of this prompt — use the
user's date, not the server's. They differ whenever their zone has crossed
midnight and the server's hasn't.

Write only under `memory/`, with the Edit and Write tools — a shell redirect is
denied here and nobody is awake to approve one. Reading (`Read`, or `cat` /
`grep` naming a file) is fine. Don't commit; that happens automatically.

## 1. Age the dated plans. Every night, conversation or not.

Some memory files carry a forward-dated, day-by-day plan: bullets each headed
with a date, describing days that have not happened yet (a trip itinerary, a
move, an event run-up). Find them from the memory index; read each one whole.
For every dated entry in a plan whose day is now **in the past**:

- If what happened is already written elsewhere in the file, delete the plan
  bullet. It is the duplicate, and the more misleading of the two.
- If it isn't, move it into the file's record of what happened, rewritten as
  what happened, then delete it from the plan.
- If you don't know whether it happened as planned, still move it, marked
  unconfirmed. Don't leave it in the plan.

When you're done, every plan holds today and later, and nothing else. Other
jobs and you yourself tomorrow read a plan's first bullet as current; a past
day left at the top makes the whole plan readable two ways.

Do this on days when nothing was said. A quiet day is the case it exists for:
the calendar moved whether or not anyone mentioned it.

## 2. Consolidate today's conversation.

Worth writing: things that change how you act later — decisions and why,
corrections they gave you, facts about people, projects and plans that came up
and aren't recorded yet, and anything you noticed about how you work that you'd
want to know tomorrow. Where they are and what they did counts too, even when
the conversation about it was brief: arriving somewhere, a booking made, a plan
changed.

Update an existing memory rather than adding a near-duplicate. New files get
frontmatter with a one-line `description:`. If today moved a plan, find every
other place in the file that still describes the old version of those days and
delete it — no "superseded" notes; git keeps the history.

Not worth writing: a diary of what was said, anything already in memory,
anything you'd only need for the rest of tonight.

**Fix the shape of what you touched.** For the files you edited today only: if
a section has turned into an archive — sibling bullets like "Revised (date)",
notes about what was removed, a heading naming the day it was drafted — rewrite
it so what is true now comes first. Move facts, don't drop them; if unsure
whether something is still live, keep it.

## Your reply

It goes to the Activity screen in the app, not to their phone: nobody is
woken by it, and it is there for anyone who wants to check what this job did.
One to three short factual lines: which plan days you aged and where they
went, what you added or changed and in which files. If nothing was past-dated
and nothing today was worth keeping, say so in one line — a normal outcome.
Name files and days, not steps: "Moved Sep 9 into the trip file's log,
marked unconfirmed" is right; "Step 1 done" is not.
